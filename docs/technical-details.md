## 信頼区間の作り方で直した不具合と残る注意

README「信頼区間の幅（2026-09-21 改訂）」の続き。

同時に区間の作り方の不具合を 3 件直した。

1. **区間は `stan` を中心に作られていたのに、公表する点推定は BMA 合成の `bayes_*`** だった。凍結データで `|bayes − stan|` は ERA 最大 0.760（σ の 0.65 倍相当）で、ずれは小さくない。
2. **正規分布の分位点を固定 seed の 5,000 draws から取っていた**ため、標本分位点のずれ（seed 42 で 95% −0.0191σ / 80% −0.0331σ）が**全選手に同じ向きで**乗っていた。旧出力の平の σ に当てると **95% −0.0028 OPS / 80% −0.0048 OPS**。閉じた形の分位点に替えて解消（外国人経路も同時に揃えた）。
3. ERA 下限の 0 クリップを再センタリングの後へ移した。

いずれも点推定の値は変えていない（`marcel_*` / `stan_*` / `bayes_*` の全列が 1 つも変わらないことを確認済み）。

⚠️ **σ の fit は 打者 PA≥100 / 投手 IP≥30 でしか行っていない。** 実際には予測 311 人のうち 124 人（40%）が PA<100、302 人のうち **152 人（50%）が IP<30**（runtime が食わせる生の予測 IP で数えた値）で、そのまま当てると検証していない領域へ外挿になる。`sigma_model.pt_floor` で**台の下端の値で頭打ち**にしてあり、**係数もこの頭打ちを当てた上で fit している**（足切りは実績で行うので、実績は閾値を超えたのに予測が下端未満という訓練行が打者 194・投手 240 ある。当てる変換で fit しないとそこが食い違う）。

🔴 **予測 IP に投球回の表記換算を当ててはいけない。** 実績 IP は NPB 表記（"10.2" = 10 と 2/3 回）だが、**Marcel が書く予測 IP は平均の小数**で、実データでは小数第 1 位が 3 以上の行が 61% ある。換算すると 25.9 → 28.0 と壊れる。

⚠️ **区間の幅は `stan` の残差 sd 由来、中心は BMA 合成**という割り切りが残っている。実測の被覆率で追認しているが、幅の根拠と中心の定義は別物。

⚠️ **`data/projections/foreign_*_2026.csv` の区間は旧方式（標本分位点）のまま。** 凍結したので再生成していない。実測（**n=8**）で**上下の半幅の差**が平均 +0.0025 OPS（＝**中心のずれ自体は +0.00125**・最大 0.0045）、95%/80% の幅の比が **1.5221**（閉じた形なら 1.5294）。

## ベイズ統合の技術詳細

[npb-bayes-projection](https://github.com/yasumorishima/npb-bayes-projection) で検証済みのStan階層ベイズモデルを統合済み（7フェーズ中6フェーズ完了）。

### 予測アーキテクチャ — 4層階層

```
Layer 1: Marcel法（基盤 — 3年加重平均 + 年齢調整）
Layer 2: Stan/Ridge補正（K%/BB%/BABIP/年齢で微調整）
Layer 3: ML（XGBoost/LightGBM）
Layer 4: BMA統合（Marcel 35% + Stan 40% + ML 25%）→ 80%/95% CI付き
  ↓
外国人選手: 前リーグ成績 × Stan v2モデル → 個別NPB予測
  ↓
モンテカルロ10,000回 → チーム勝数分布 → P(優勝)/P(CS)
```

### 設計上の判断
- **Stanはランタイムで動かさない** — posteriors.jsonに事後分布パラメータを保存、推論時はNumPyサンプリングのみ（RPi5 4GB RAM対応）
- **外国人選手は全員Web検証済み** — 24人の英語名・出身リーグ・前リーグ成績を個別に確認
- **MLB移籍選手はロースターフィルタで除外** — roster_current.pyで2026公式ロースターに照合
- **不確実性がエンドツーエンドで伝播** — 選手CI → チームMonte Carlo → 優勝確率
